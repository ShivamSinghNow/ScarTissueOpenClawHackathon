This PR reintroduces the bug fixed in commit 2b6911d9af58ba5a03b9c7102ab47c8aeee70c16. The simplified slicing logic breaks the critical invariant that tool response messages must remain paired with their parent AIMessage containing the corresponding tool_calls. When summarization triggers during multi-tool agent conversations, this change will orphan ToolMessage responses by summarizing away the AIMessage that requested them, causing "No tool call found for function call output" API errors. The original fix ensured that when the cutoff lands on tool messages, the code moves backward to include the paired AIMessage, maintaining the required call-response chain that agent APIs depend on.

This PR reintroduces a bug that was fixed in commit d84eef667af9bd2480b5c50852dad0b393f40c29. The change removes the check for `AIMessage.tool_calls` in `get_buffer_string`, reverting to only checking the deprecated `additional_kwargs["function_call"]` field. Modern LLM providers (OpenAI, Anthropic, etc.) now return tool invocations via the `tool_calls` field, not `function_call`. This regression will cause tool invocation data to be silently lost when formatting message buffers, breaking tool-using agents and chains that rely on `get_buffer_string` to preserve complete conversation context including function/tool calls.
